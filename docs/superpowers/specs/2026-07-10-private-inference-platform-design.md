# ShareGuard 私有推理平台设计

## 1. 目标

本阶段把现有 ShareGuard 比赛演示升级为可用于评委展示和早期客户试点的私有影像风险工作台。平台以 Web 工作台承载用户流程，以版本化 API 承载模型能力，并确保模型权重、内部阈值、融合参数、服务器路径和逐子模型分数不会进入公开仓库或客户端响应。

第一阶段交付的是可安全部署的同步试点服务，不是完整的多租户商业 SaaS。系统需保留后续接入异步任务、组织账户、计费、Webhook 和私有化部署的清晰接口。

## 2. 已选产品路线

### 方案 A：仅做公开网站

优点是演示直接、部署便宜；缺点是无法支撑客户系统接入，也容易把产品降格为一次性检测页面。

### 方案 B：仅出售模型 API

优点是接口清晰、便于集成；缺点是容易陷入按次调用的价格竞争，且评委和非技术客户难以看到完整业务价值。

### 方案 C：Web 工作台 + 私有 API + 企业私有部署

采用本方案。公开网站负责品牌和安全示例，邀请制工作台负责真实分析流程，私有 API 作为统一能力底座；获得企业客户后，再提供独立 VPC 或本地容器部署。

## 3. 第一阶段范围

### 包含

- 保留 GitHub Pages 静态演示，但静态页面只运行明确标识的示例案例，不接触真实模型。
- 在同一私有服务中提供 Web 工作台和 `v1` API，避免在浏览器中保存机器调用密钥。
- 提供单图同步分析、三级业务决策、风险说明、传播退化视图和可归档报告。
- 提供 Bearer Token 机器认证、上传限制、CORS 白名单、安全响应头和统一错误结构。
- Pilot 与 Production 通过只读归档或私有签名地址加载模型，并在启动时校验 SHA-256；已解压目录仅用于本地开发。
- 推理进程常驻并复用已加载模型；同一 GPU 默认串行执行推理，防止并发显存峰值。
- 默认只在内存中处理上传文件，不把原图写入磁盘，不在日志中记录文件内容或模型内部参数。
- 保留旧 `/api/analyze` 端点作为临时兼容入口，并在响应中标记弃用；新接入统一使用 `/v1/analyze`。

### 不包含

- 原生 iOS、Android 或桌面应用。
- 公开下载模型、浏览器端推理、客户端 SDK 内嵌权重。
- 公共注册、支付、团队角色和完整多租户权限系统。
- 视频、音频和文档检测。
- 第一阶段自行实现持久化任务队列；只有在真实负载证明同步接口不足后才引入异步任务。
- 将模型结果表述为司法鉴定、事实证明或真实性证书。

## 4. 部署边界

```text
公开 GitHub Pages
  -> 只展示安全样例和产品流程
  -> 不包含 API 密钥、模型地址或权重

邀请制私有站点
  -> Web 工作台与 API 同源
  -> 外层访问网关限制评委和试点客户
  -> /v1/analyze 处理真实图片

私有推理容器
  -> 常驻 GPU 进程
  -> 只读模型目录或短期签名下载地址
  -> 不向客户端返回原始模型输出
```

GitHub 只保存源代码、测试、Docker 构建文件和不含秘密的配置示例。模型压缩包存放在私有对象存储、私有模型仓库或部署平台的加密卷中；模型 URL 和摘要通过部署密钥注入。

## 5. 组件设计

### 5.1 `PlatformConfig`

集中解析环境变量和命令行参数，负责以下配置：

- 运行模式：`local`、`pilot` 或 `production`。
- API Token：`SHAREGUARD_API_TOKEN`。
- CORS 白名单：`SHAREGUARD_ALLOWED_ORIGINS`，默认不允许跨域。
- 最大上传大小：默认 10 MiB。
- 最大像素数：默认 25,000,000。
- 可接受格式：JPEG、PNG 和 WebP。
- 模型摘要：`SHAREGUARD_BUNDLE_SHA256`。
- 模型版本：从私有 manifest 读取后映射为可公开版本标识。
- 最大并发推理数：第一阶段默认为 1。

`production` 模式缺少 API Token 或模型摘要时拒绝启动；`local` 模式允许无 Token 的环回地址调试。

### 5.2 `AnalysisService`

封装图片校验、推理调用、耗时统计、三级决策和公开响应构建。HTTP 层不直接读取模型内部字段。

服务输入：图片字节、文件名和请求 ID。

服务输出：只包含产品字段的 `PublicAnalysisResult`。内部 `raw`、服务器路径、融合权重、阈值、逐模型分数和私有下载地址全部丢弃。

### 5.3 `DecisionPolicy`

模型分数与业务决策分离。第一阶段使用可测试的默认策略：

- 置信度低于 0.20：`review`，显示“需要人工复核”。
- 风险等级为 `high`：`hold`，显示“建议暂缓发布”。
- 风险等级为 `medium` 或模型结论与置信度不一致：`review`。
- 其余结果：`allow`，显示“可进入后续发布流程”。

策略结果是工作流建议，不修改模型原始概率。未来可按客户、媒体类型和校准数据配置，但第一阶段不开放前端任意调阈值。

### 5.4 HTTP 网关

提供以下端点：

- `GET /v1/health`：仅表示进程存活，不触发模型加载。
- `GET /v1/ready`：表示配置有效且模型后端可接受请求。
- `POST /v1/analyze`：正式同步分析端点。
- `POST /api/analyze`：兼容旧页面，内部调用同一分析服务。
- `GET /`：私有工作台。

所有 API 响应包含 `request_id`。生产模式下，分析端点要求 `Authorization: Bearer <token>`；同源工作台由外层访问网关保护，机器 Token 不写入公开 JavaScript。

### 5.5 模型制品加载

模型加载支持两种生产方式：

1. 将已批准模型归档作为只读卷挂载到容器。
2. 使用部署密钥提供短期签名 URL，下载到私有缓存卷。

下载过程先写临时文件，校验配置的 SHA-256 后再原子替换目标文件。摘要不一致时删除临时文件并拒绝启动。每次启动从已验证归档重新生成解压缓存，避免复用被修改的旧目录。生产文档不再建议把权重上传到公开 GitHub Release、公开 Hugging Face 仓库或普通 Git 历史。

### 5.6 推理生命周期

模型在首个真实请求前完成加载，并在进程生命周期内复用。私有部署使用常驻 GPU 服务，不使用会频繁缩容到零的冷启动模式。

第一阶段通过信号量限制 GPU 并发。后续先测量 batch 1 和 batch 8 的延迟、显存及单位成本，再决定是否加入批处理、FP16、ONNX/TensorRT 或模型蒸馏。

## 6. API 契约

`POST /v1/analyze` 使用 `multipart/form-data`，字段名为 `image`。

成功响应：

```json
{
  "request_id": "sg_req_01J...",
  "model_version": "shareguard-private-v1",
  "decision": "review",
  "decision_label": "需要人工复核",
  "risk_level": "medium",
  "ai_probability": 0.71,
  "confidence": 0.64,
  "uncertainty": "medium",
  "recommended_action": "建议暂缓公开使用，并结合来源信息进行人工复核。",
  "report": {
    "report_id": "SG-20260710-XXXXXXXX",
    "report_type": "真实传播链路鉴真报告",
    "summary": "传播后仍保持中高风险，建议进入人工复核。"
  },
  "warnings": [
    "本结果为技术辅助，不替代司法鉴定或最终法律结论。"
  ],
  "latency_ms": 850
}
```

失败响应：

```json
{
  "request_id": "sg_req_01J...",
  "error": {
    "code": "unsupported_image",
    "message": "请上传 JPEG、PNG 或 WebP 图片。"
  }
}
```

公开响应不包含 `backend`、`raw`、本地路径、模型组成、融合方法、内部阈值或堆栈信息。

## 7. 安全与隐私

- 使用常量时间比较验证 Bearer Token。
- 在读取请求体前检查 `Content-Length`，超限返回 `413`。
- 使用 Pillow 解码并验证实际格式；拒绝空文件、动画图片、超大像素图片和损坏图片。
- 默认不设置 `Access-Control-Allow-Origin`；只有请求来源精确命中白名单时才返回跨域头。
- 返回 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer` 和限制性 `Content-Security-Policy`。
- 错误日志记录请求 ID、错误类别和耗时，不记录图片字节、完整文件名、Token、模型路径或内部预测字典。
- 上传内容在请求结束后释放；第一阶段不持久化原图。
- 报告编号用于产品演示和流程追踪，不声称具备司法证据链效力。

## 8. 错误处理

- 缺失或错误 Token：`401 unauthorized`。
- 请求体过大：`413 payload_too_large`。
- Multipart 字段缺失：`400 missing_image`。
- 格式不支持或图片损坏：`415 unsupported_image`。
- 像素数超限：`413 image_too_large`。
- GPU 正忙且等待队列达到限制：`429 service_busy`。
- 模型未就绪：`503 model_unavailable`。
- 其他内部错误：`500 internal_error`，客户端不接收异常文本或路径。

## 9. 测试策略

- 单元测试覆盖配置解析、Token 验证、CORS 白名单、文件大小、格式和像素限制。
- 单元测试覆盖三级决策的边界和产品响应脱敏。
- HTTP 集成测试覆盖健康检查、认证失败、合法上传、旧端点兼容和统一错误结构。
- 模型制品测试覆盖正确摘要、错误摘要、缓存复用和恶意压缩包路径。
- 现有 mock 和假 predictor 测试继续作为无 GPU CI 路径。
- 私有 GPU 环境增加一次真实 bundle 冒烟测试，但不把权重或结果样本上传到公共 CI artifact。
- 静态泄漏测试扫描公开目录，拒绝模型后缀、内部参数名、私有 URL 和秘密文件。

## 10. 验收标准

1. GitHub Pages 在没有后端时仍能完整展示明确标识的安全示例。
2. 私有站点可以通过真实 bundle 完成一张 JPEG、PNG 或 WebP 图片分析。
3. `/v1/analyze` 返回三级业务决策和报告摘要，且不泄露内部模型字段。
4. 非法 Token、超大文件、损坏图片和不允许的跨域请求均被拒绝。
5. 配置错误的 SHA-256 时服务不加载模型。
6. 所有自动化测试在无 GPU 环境通过；GPU 冒烟测试有独立运行说明。
7. Docker 镜像不包含模型权重，运行时以只读卷或私有签名 URL 获取模型。
8. 现有未提交页面和模型脱敏改动被保留，不因本阶段工作回退。

## 11. 后续阶段

完成三个真实试点并收集任务量、峰值并发、人工复核率和误判成本后，再实施异步 `POST /v1/scans`、任务状态查询、Webhook、多租户、审计数据库和用量计费。企业私有部署沿用同一容器和 API 契约，只替换身份系统、存储策略和网络边界。
